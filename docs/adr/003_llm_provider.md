# ADR 003. Claude API с собственными инструментами для агента

- Статус: принято
- Дата: 2026-10-21

## Контекст

Агенту нужно читать код и логи блока, вносить правки, запускать тесты и открывать pull request. Проверка области доступа ([ADR 002](002_agent_changes_via_pull_request.md)) должна выполняться в нашей инфраструктуре, рядом с клоном репозитория. Задача может занимать десятки шагов, поэтому модели нужны надёжный вызов инструментов и большой контекст.

Рассмотренные варианты:

1. **Claude API + собственные инструменты** (Tool Runner из Python SDK `anthropic`): цикл агента и выполнение инструментов в нашем воркере.
2. **Claude Managed Agents**: цикл агента и песочница на стороне Anthropic.
3. **Открытая модель на своём сервере**: без внешнего провайдера, но нужен GPU-сервер.

## Решение

Выбран вариант 1: модель `claude-opus-5-5`, адаптивное рассуждение, потоковые ответы.

- Инструменты описаны в воркере. Перед выполнением каждый вызов проверяется на соответствие схеме и области блока.
- В запросе к модели только контекст задачи. Секреты отфильтровываются до отправки ([NFR-S3](../requirements/non_functional.md)).
- Расход токенов пишется в `task_message`. Бюджет задачи ограничен ([NFR-M3](../requirements/non_functional.md)).

## Последствия

Плюсы:

- Проверка границ блока и доступ к репозиторию остаются у нас.
- Официальный Python SDK встраивается в существующий backend без отдельной инфраструктуры.
- Модель можно заменить: она задаётся настройкой, и инструменты от неё не зависят.

Минусы и риски:

- Зависимость от внешнего провайдера и его доступности. Если провайдер недоступен, задача ставится на паузу, а мониторинг работает без него.
- Фрагменты кода и логов клиента уходят провайдеру. Это нужно согласовать с заказчиком до подключения.
- Стоимость задачи переменная. Её ограничивают бюджет токенов и остановка задачи пользователем.
