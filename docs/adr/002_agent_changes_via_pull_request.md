# ADR 002. Агент меняет систему клиента только через pull request

- Статус: принято
- Дата: 2026-10-21

## Контекст

Исходная идея — дать модели напрямую редактировать файлы на сервере клиента. Пилотная система работает в production: каждое утро она формирует планы выпечки для пекарен сети. Ошибочная правка, сделанная напрямую на сервере, сорвёт рабочий день точек, и откатить её быстро будет нечем.

Рассмотренные варианты:

1. **Прямая правка на сервере**: агент получает SSH-доступ и меняет файлы в рабочем каталоге.
2. **Правка на сервере с подтверждением**: агент показывает diff, человек нажимает «применить», изменения пишутся на сервер по SSH.
3. **Правка через репозиторий**: агент работает с клоном клиентского репозитория в изолированном каталоге, вносит изменения в отдельную ветку и открывает pull request. На сервер изменения попадают только через CI/CD после одобрения.

## Решение

Выбран вариант 3.

- Агент не имеет доступа к серверу клиента. Probe на сервере работает только на отправку статусов.
- Инструменты агента (`list_files`, `read_file`, `write_file`, `run_tests`, `open_pull_request`) проверяют путь по области доступа блока ([FR-15](../requirements/functional.md)). Путь нормализуется до проверки, поэтому `../` и символические ссылки за пределы области отклоняются.
- Ветка агента называется `agent/<id задачи>-<блок>`. В описание pull request входят ссылка на задачу, причина, изменения и способ проверки.
- Ветка main клиентского репозитория защищена: слияние только через pull request, нужно одобрение и успешные тесты.
- Развёртывание выполняет GitHub Actions после слияния: `git pull` и перезапуск на сервере. После него Pult запускает внеочередную проверку блока.

## Последствия

Плюсы:

- Каждая правка проходит ревью и тесты, видна в истории, откатывается через revert.
- Ошибка агента не попадает в production без участия человека.
- Граница ответственности блока проверяется кодом, а не только инструкцией в промпте.

Минусы и риски:

- Срочное исправление идёт дольше на время CI и развёртывания, это примерно 5–10 минут.
- Пилотная система должна разворачиваться из репозитория. Для неё нужно добавить в CI задание развёртывания: сейчас код обновляется на сервере вручную.
- Правки вне репозитория (секреты в `.env`, crontab) агенту недоступны и остаются за разработчиком.
