# Тест-план

## Объект и цель

Объект — backend (FastAPI) и frontend (React) Pult. Цель — подтверждать требования из [functional.md](../requirements/functional.md) и [non_functional.md](../requirements/non_functional.md) автоматическими проверками на каждый pull request, чтобы регрессии не попадали в main.

## Уровни тестирования

| Уровень | Что проверяется | Инструменты | Статус |
|---|---|---|---|
| Модульные | Чистые функции и компоненты: вычисление статуса, настройки, отображение статуса | pytest, Vitest, Testing Library | есть |
| Интеграционные | API через `TestClient`, модели и ограничения БД | pytest, SQLite в памяти, PostgreSQL в CI | есть (SQLite), PostgreSQL — ПР5 |
| Контрактные | Соответствие API контракту OpenAPI | schemathesis, Bruno | ПР6 |
| Сквозные (E2E) | Пользовательские сценарии в браузере | Playwright | ПР7 |
| Нагрузочные | NFR-P4: p95 ≤ 300 мс при 50 пользователях | k6 | ПР9 |
| Безопасность | Зависимости, секреты, статический анализ | pip-audit, npm audit, CodeQL | ПР9 |

## Критерии входа и выхода

Вход: открыт pull request, ветка собирается, изменён код или тесты.

Выход (условие слияния):
- все тесты проходят;
- покрытие backend не ниже 90 % с учётом ветвлений, покрытие компонентов frontend не ниже 90 %;
- нет ошибок Ruff, mypy, ESLint, Prettier, commitlint и общих хуков;
- все обсуждения ревью закрыты.

## Тест-кейсы: статус блока (FR-09)

Порядок серьёзности: `fail > warn > unknown > ok`. «Нет данных» ниже «предупреждения»: отсутствие данных бывает и при плановых работах, а предупреждение — это подтверждённая проблема. Длительное отсутствие данных станет отдельным оповещением мониторинга.

| ID | Условие | Ожидаемый результат | Тест |
|---|---|---|---|
| ST-01 | Свежий результат ok / warn / fail | Статус совпадает с результатом | `test_fresh_result_keeps_its_status` |
| ST-02 | Результата нет | `unknown` | `test_no_result_is_unknown` |
| ST-03 | Результат ровно три интервала назад | Ещё действителен | `test_result_on_stale_boundary_is_still_valid` |
| ST-04 | Результат старше трёх интервалов | `unknown` | `test_result_older_than_three_intervals_is_unknown` |
| ST-05 | Интервал 300 с, результат 500 с назад | Действителен (порог 900 с) | `test_stale_threshold_depends_on_check_interval` |
| ST-06 | У блока нет проверок | `unknown` | `test_block_without_checks_is_unknown` |
| ST-07 | Несколько проверок с разными статусами | Худший статус | `test_block_takes_worst_check_status` (7 наборов) |
| ST-08 | Текущее время без часового пояса | `ValueError` | `test_naive_now_is_rejected` |
| UI-01 | Каждый статус в StatusBadge | Подпись, иконка и CSS-класс статуса | `StatusBadge.test.tsx` |
| UI-02 | Иконка статуса | Скрыта от экранного диктора, подпись доступна | `StatusBadge.test.tsx` |

## Дефекты

Найденная ошибка оформляется задачей с меткой `bug`. Исправление начинается с теста, который воспроизводит ошибку. Pull request с исправлением содержит этот тест.
