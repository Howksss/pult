# Модель данных

Схема: [er_diagram.puml](er_diagram.puml), изображение: [er_diagram.png](er_diagram.png).

| Сущность | Назначение |
|---|---|
| `app_user` | Пользователь Pult |
| `project` | Проект: система клиента и её репозиторий |
| `project_member` | Участие пользователя в проекте и его роль (владелец, разработчик, заказчик) |
| `block` | Блок графа: тип, имя, координаты на холсте |
| `block_link` | Направленная связь между двумя блоками |
| `block_scope` | Шаблон пути в репозитории, к которому у агента этого блока есть доступ на чтение или запись |
| `health_check` | Настройка проверки блока: метод, цель, интервал, таймаут |
| `check_result` | Результат одной проверки |
| `agent_task` | Задача агенту по блоку |
| `task_message` | Сообщение в чате задачи (пользователь, агент, результат инструмента) и расход токенов |
| `change_request` | Pull request, открытый по задаче, и его ревью |
| `deployment` | Развёртывание слитого pull request |
| `audit_event` | Запись журнала аудита |

Перечислимые типы (`member_role`, `block_kind`, `scope_access`, `check_method`, `check_status`, `task_status`, `message_role`, `cr_status`, `deploy_status`) реализуются как `ENUM` PostgreSQL.

## Нормализация

- **1НФ.** Все атрибуты атомарны. Списки (области доступа, проверки, участники) вынесены в отдельные таблицы, а не хранятся строкой через запятую. Поле `jsonb` используется только там, где структура определяется внешней стороной и не участвует в запросах как набор атрибутов: содержимое сообщения модели (`task_message.content`) и детали события аудита (`audit_event.payload`).
- **2НФ.** Единственный составной ключ — `project_member (project_id, user_id)`. Его неключевой атрибут `role` зависит от пары целиком: роль у одного и того же человека в разных проектах разная.
- **3НФ.** Транзитивных зависимостей нет:
  - статус блока не хранится в `block`, он вычисляется по последнему `check_result` его проверок;
  - у `block_link` нет `project_id`, проект определяется через связанные блоки;
  - ссылка на pull request не хранится, она собирается из `project.repo_full_name` и `change_request.pr_number`;
  - проект задачи определяется через `agent_task.block_id → block.project_id`.

Ограничения целостности: `UNIQUE (project_id, name)` в `block`, `CHECK (source_block_id <> target_block_id)` в `block_link`, `UNIQUE (task_id)` в `change_request` (у задачи не больше одного pull request).
