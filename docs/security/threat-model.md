# Модель угроз

Метод — STRIDE по потокам данных из [контейнерной диаграммы](../architecture/container_diagram.png). Самые ценные активы: код и данные системы заказчика, токены (probe, GitHub, Claude API, Telegram) и право менять систему заказчика через pull request.

## Границы доверия

1. Интернет → nginx → API: пользователи и probe.
2. API и worker → внешние сервисы: GitHub, Claude API, Telegram.
3. Worker → рабочие копии репозитория заказчика: здесь действует агент.

## Угрозы и меры

| № | STRIDE | Угроза | Мера | Статус |
|---|---|---|---|---|
| T1 | Spoofing | Чужой отправляет результаты проверок от имени probe | Токен проекта в `X-Probe-Token`, в БД только SHA-256, токен действует только на `/probe/results` своего проекта (NFR-S5). Тесты 401 и 422 на чужие проверки | сделано |
| T2 | Spoofing | Неавторизованный пользователь меняет граф | Операции графа в API без аутентификации. На рабочем сервере всё, кроме `/api/v1/probe/` и `/api/health`, закрыто HTTP Basic на обратном прокси, только по HTTPS (#51) | **частично**: один общий вход; учётные записи пользователей (сессия HttpOnly, Argon2id, NFR-S4) — 0.3.0 |
| T3 | Tampering | Агент пишет файлы вне области блока, в том числе через `../` и символические ссылки | Нормализация пути и проверка по `block_scope` до любой операции (FR-15, NFR-S1) | спроектировано (ADR 002), реализуется с агентом |
| T4 | Tampering | Правка агента попадает на сервер заказчика без проверки | Только ветка и pull request, защита main, одобрение человеком, CI перед развёртыванием (ADR 002, NFR-S2) | спроектировано |
| T5 | Tampering | Подделка записей лога через `X-Request-ID` | Принимается только `[A-Za-z0-9-]{1,64}`, иначе генерируется свой | сделано (#44) |
| T6 | Repudiation | Нельзя установить, кто одобрил правку или что сделал агент | `audit_event` для действий пользователей и агента. Автора удалить нельзя (`ON DELETE RESTRICT`), записи хранятся год (NFR-S6) | схема сделана (#23) |
| T7 | Information disclosure | Секреты заказчика уходят в языковую модель | Файлы `.env*`, `*.key`, `*.pem` исключаются из контекста, токеноподобные строки маскируются (NFR-S3) | спроектировано (ADR 003) |
| T8 | Information disclosure | Токен бота или пароль попадают в логи | В лог пишутся класс ошибки и поля запроса, без тел и URL с токеном. Есть тест | сделано (#31, #44) |
| T9 | Information disclosure | Секреты попадают в репозиторий | `.gitignore` для `.env`, хук `detect-private-key`, сканирование секретов GitHub с push protection | сделано |
| T10 | Denial of service | Огромная пачка от probe или поток запросов | Не больше 500 результатов в пачке, ограничение длины полей в контракте. На обратном прокси `limit_req` по адресу и `client_max_body_size 1m` (#51) | сделано |
| T11 | Elevation of privilege | Уязвимая зависимость или образ | Dependabot (pip, npm, Docker, Actions), `pip-audit` и `npm audit` в CI, CodeQL, образы без root | сделано |
| T12 | Elevation of privilege | SQL-инъекция | Только ORM и параметризованные запросы, правила Ruff `S` (bandit) в CI | сделано |

## Автоматические проверки

| Что | Где |
|---|---|
| Уязвимые зависимости Python | `pip-audit -r backend/requirements.txt`, задание CI `security` |
| Уязвимые зависимости npm (production) | `npm audit --omit=dev --audit-level=high`, задание `security` |
| Статический анализ кода | CodeQL (Python, TypeScript), правила Ruff `S` |
| Секреты в коммитах | Secret scanning и push protection GitHub, хук `detect-private-key` |
| Обновления | Dependabot, раз в неделю |

Открытый риск T2 закрыт на прокси только частично: общий вход подходит для одного пилота, но не для нескольких клиентов на одном экземпляре. Подключать второго клиента можно только после учётных записей и разграничения по проектам в 0.3.0.
