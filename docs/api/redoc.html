Pult API (1.1.0)

Download OpenAPI specification:Download

License: MIT

Контракт API Pult версии 1. Источник истины для backend, frontend, probe и коллекции Bruno: сначала меняется этот файл, потом код. Тесты backend сверяют каждый ответ с контрактом. Несовместимые изменения выпускаются как /api/v2, совместимые — как новые поля и эндпоинты в v1 (журнал: docs/api/changelog.md). Аутентификация: cookie сессии для интерфейса или заголовок X-API-Key для интеграций; probe — X-Probe-Token. 401 — не удалось установить, кто вы; 403 — роли в проекте не хватает. Ошибки возвращаются в формате application/problem+json (RFC 9457): type, title, status, detail и для ошибок проверки — errors. 400 — тело не является JSON, 422 — JSON не прошёл проверку по схеме. Списки: пагинация limit и offset, общее число в заголовке X-Total-Count, фильтры в параметрах запроса.

Добавить проверку блоку

Цель и настройки проверяются по типу. Адреса во внутренней сети (localhost, частные, link-local) отклоняются, если на сервере не включён ALLOW_PRIVATE_TARGETS.

Authorizations:
userSessionapiKey
path Parameters
block_id
required
integer >= 1
Request Body schema: application/json
required
name
string or null <= 120 characters
method
required
string (CheckMethod)
Enum: "heartbeat" "http" "log_pattern" "exit_code" "tls" "tcp"

http, tls и tcp выполняет сам Pult. heartbeat, exit_code и log_pattern присылает сервер клиента.

target
required
string [ 1 .. 500 ] characters

http — URL, tls — хост или хост:порт, tcp — хост:порт, остальные — свободный текст

interval_sec
integer [ 10 .. 604800 ]
Default: 60
timeout_sec
integer [ 1 .. 60 ]
Default: 10
enabled
boolean
Default: true
config
object

http — method (GET, HEAD), expect_status (до 10 кодов), contains (до 200 символов), warn_latency_ms; tls — warn_days (1–365, по умолчанию 14), fail_days (меньше warn_days, по умолчанию 3); остальные типы — пустой объект.

probe

Приём результатов проверок с сервера клиента

Принять пачку результатов проверок от probe

Probe на сервере клиента отправляет результаты пачкой. Токен проекта передаётся в заголовке X-Probe-Token и даёт право только на этот эндпоинт (NFR-S5). Пачка принимается целиком или отклоняется целиком. Если в ней есть проверка чужого проекта или несуществующая проверка, ответ 422 со списком таких health_check_id в errors. Probe должен убрать эти записи и повторить отправку остальных, иначе данные будут потеряны. Задания по расписанию и heartbeat отчитываются этим же запросом одной строкой curl в cron. Если такая проверка молчит дольше полутора интервалов, блок получает статус fail («пропущен запуск»).
