Тест-кейсы и критерии выхода описаны в [тест-плане](../quality/test-plan.md).

## Как запустить

```bash
cd backend
pytest                                   # тесты + покрытие в терминале
pytest --cov-report=html                 # HTML-отчёт в backend/htmlcov/index.html

cd frontend
npm test                                 # тесты + покрытие, HTML в frontend/coverage/index.html
```

Тесты на PostgreSQL (`test_pg_schema.py`, `test_pg_status_view.py`) требуют `TEST_DATABASE_URL`. Без него эти 15 тестов пропускаются.

## Позитивные и негативные сценарии

Кроме обычных сценариев, тесты проверяют ошибки и границы:

- граница свежести: результат ровно три интервала назад ещё действителен, на секунду старше — уже `unknown` (`test_status.py`, `test_graph_status.py`);
- наивное время `now` отклоняется с `ValueError`, наивное время от probe трактуется как UTC;
- блок без проверок, проверка без результатов, неизвестный id блока, пустой список блоков;
- probe без токена или с чужим токеном получает 401, результаты чужих проверок — 422 со списком id;
- 404 на несуществующий проект, 409 на дубль имени блока, 422 на неверные поля и пустое обновление, связь блока с самим собой отклоняется и API, и ограничением БД;
- `/api/ready` возвращает 503 в формате problem+json без базы, ответ 502 от Telegram не выбрасывает исключение, токен бота не попадает в логи.

## Найденные ошибки

В коде приложения тесты ошибок не нашли. Они поймали две ошибки в изменениях от ИИ-ассистента до коммита (подробности в ai_usage_and_risks.md):

1. Рефакторинг `submit_results`: вариант с `dict(result.tuples())` прошёл mypy, но 4 теста упали с `TypeError: 'ChunkedIteratorResult' object is not subscriptable`. Исправлено на `dict(result.tuples().all())`.
2. Черновик тестов для `graph_status.py` пропускал подмену интервала проверки таймаутом: граница устаревания проверялась только с одной стороны.
