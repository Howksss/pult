## [Unreleased]

### Added

- Ограничения предметной области в базе (миграция `0007`): 23 правила `CHECK`, одна связь между блоками в одну сторону, одна идущая выкатка на pull request, `RESTRICT` для авторов задач и ревью; индексы под запросы и удаление лишних (`0008`); комментарии `COMMENT ON` ко всем таблицам, столбцам, типам, ограничениям и индексам (`0009`); тестовые данные той же командой `alembic -x seed=demo upgrade head` (`0010`), демо-вход для трёх ролей (#103).
- Словарь данных `docs/module5/data-dictionary.md` из живой схемы (`scripts/data_dictionary.py`), ADR 004 о миграциях, демонстрация транзакций и уровней изоляции, инструкция по копиям с RPO и RTO (#103).
- Копии БД: недельные хранятся 8 недель, отправка в облачное хранилище S3 через rclone, ежемесячная проверка восстановления `deploy/db/restore-check-compose.sh`; `verify.sh` сверяет ещё и структуру (#103).
- Диагностика проверок: у результата `message`, класс ошибки `error_kind` и подробности `details`; у проверки имя, настройки `config` и флаг `enabled`; новые типы `tls` и `tcp`, миграция `0004` (#90).
- Процесс `worker` (`python -m app.worker`, профиль compose `checks`) сам выполняет проверки `http` (код, время, текст в ответе), `tls` (срок сертификата), `tcp` (открытый порт) и записывает результаты с подробностями (#90).
- `GET /api/v1/blocks/{id}/checks`: проверки блока с последним результатом, подробностями и историей; в графе у блока `reason`, `checks_total`, `checks_problem` (#90).
- Задание или heartbeat, молчащие дольше полутора интервалов, — статус «сбой» с причиной «нет отчёта N мин»; обёртка `pult-run` для cron в `docs/api/README.md` (#90).
- Панель блока показывает проверки: причина, подробности, вывод stderr или ответ сервера, история; на узле — причина вместо описания и доля проблемных проверок (#90).
- `scripts/demo_feed.py` — демо-результаты через эндпоинт probe (#90).
- Настройка проверок: `POST /api/v1/blocks/{id}/checks`, `PATCH`/`DELETE /api/v1/checks/{id}`, `POST /api/v1/checks/{id}/run`; цель и настройки проверяются по типу; в панели блока форма, «Проверить сейчас», выключение, удаление, строка для cron (#92).

- Шаблон сайта nginx `deploy/proxy/nginx-site.conf` и ежедневная копия БД из контейнера `deploy/db/backup-compose.sh` (#51).
- Область доступа блока: `GET`/`POST /api/v1/blocks/{id}/scopes`, `PATCH`/`DELETE /api/v1/scopes/{id}`, проверка шаблонов и путей (`services/scope.py`), уникальность пути в блоке (миграция `0005`), раздел «Область агента» в панели блока (#94).
- Учётные записи: регистрация, вход и выход по email и паролю (Argon2id), сессия в cookie HttpOnly (миграция `0006`); проекты пользователя и создание проекта с токеном probe; участники и роли «владелец», «разработчик», «заказчик»; права на всех эндпоинтах; экран входа, создание первого проекта, переключатель проектов и участники в шапке; `scripts/add_member.py` (#96).
- Шкала последних суток в проверке: у проверки `timeline` (24 часовых отрезка с числом результатов `ok`, `warn`, `fail`) и `failing_since`; в панели два ряда по 12 часов с номером под каждым, доля сбоев и предупреждений — высотой цвета, расшифровка часа под курсором вместо полосы последних 40 результатов и «Сбой с 06:10, 1 ч 50 мин» (#98).

### Changed

- ER-диаграмма приведена к схеме (сессии, диагностика, токен probe, типы ключей), тест сверяет её с моделями; CI проверяет воспроизводимость миграций и их откат (#103).
- Ручной запуск проверки не держит транзакцию открытой во время сетевого запроса, уведомление в Telegram уходит после фиксации; ошибка в запросе явно откатывает транзакцию; таймаут проверки не больше интервала (422); повторная связь между теми же блоками — 409 (#103).
- Новый визуальный язык доски: блоки — стеклянные плиты на рендерах Blender, стеклянные панель масштаба, кнопка «Отправить» и буква P в логотипе; одна тёмная тема без переключателя, зерно поверх экрана; статус точкой и словом без плашки, сбой без свечения — тёмно-красная подложка; подписи связей без рамок; шрифт Onest вместо Inter, текст не мельче 14 px; мини-карта убрана (#88).
- Шапка: название проекта вместо «Проект N», по риске на блок цветом статуса, «N из M работают», время обновления; итог системы ведёт к проблемному блоку (#88).
- `GET /api/v1/projects/{id}/graph` отдаёт `project_name` (#88).

- Новый интерфейс графа: тёмная и светлая темы, карточки блоков с иконкой типа и свечением при сбое, подписи связей плашками, движение данных по исправным связям, подсветка связей выбранного блока, плавающая панель блока со связями и полем задачи агенту, полоса здоровья в шапке, мини-карта (#49).
- Блоки перетаскиваются, положение сохраняется через `PATCH /api/v1/blocks/{id}` (#49).
- Раскладка демо-данных без пересечения связей с блоками (#49).
- Иконки Iconsax вместо `lucide-react`: двухтоновые для типов блоков, линейные для кнопок, свои кнопки масштаба (#73).
- Статус показывается цветной точкой и словом вместо символа в кружке, у каждого статуса подсказка с объяснением. В шапке итог системы одной фразой, клик открывает проблемный блок; счётчики только ненулевых статусов (#71).

### Security

- Операции API требуют сессию пользователя и роль в проекте, чужие проекты отвечают 404; закрыт риск T2 (#96).
- Защита от SSRF в проверках: внутренние адреса отклоняются при сохранении и при выполнении, соединение закреплено за проверенным адресом, перенаправления проверяются по одному; `ALLOW_PRIVATE_TARGETS` для локальной разработки (#92).
- Рабочее развёртывание за обратным прокси: порты compose только на `127.0.0.1`, HTTPS, HTTP Basic до учётных записей, ограничение частоты, probe по токену без Basic (#51).
- Модель угроз STRIDE, `pip-audit` и `npm audit` в CI, CodeQL, Dependabot (#45).
- FastAPI 0.157.0 и Starlette 1.9.0 вместо 0.115.6 и 0.41.3: закрыты 7 известных уязвимостей Starlette (#45).

### Fixed

- Метрики HTTP снова группируются по шаблону маршрута: новый FastAPI заворачивает подключённые роутеры, и метка `route` получала реальный путь с идентификатором (#45).
- Начало сбоя, который длится дольше суток, ищется и за пределами шкалы: первый результат после последнего успешного. Раньше «Сбой с» показывал начало шкалы. Длительность больше суток выводится днями, время начала — с датой: «Сбой с 3 ноября 14:05, 14 дней» (#100).

## [0.1.0] - 2026-10-21

Первый учебный релиз: каркас backend и frontend, проектная документация, процесс командной работы.

### Added

- Репозиторий, README с назначением системы, ролями и стеком, каркас backend на FastAPI и frontend на React + Vite, docker-compose (#1).
- Проектная документация: BPMN As-Is и To-Be, функциональные и нефункциональные требования, контекстная диаграмма и контейнеры C4, ER-модель в 3НФ, ADR 001–003 (#2).
- Эндпоинт `GET /api/health` со статусом и версией приложения, ответ описан моделью `HealthResponse` в OpenAPI (#3, PR #10).
- Конфигурация через pydantic-settings: БД, Claude API, GitHub, CORS, интервал проверок, а также `.env.example` (#4, PR #11).
- SQLAlchemy-модели `project`, `block`, `block_link`, `health_check`, `check_result` с ограничениями целостности и индексом по `block.project_id` (#5, PR #12).
- CI в GitHub Actions: ruff и pytest для backend, сборка frontend; устаревшие прогоны отменяются (#6, PR #9).
- Модель ветвления, правила ревью и релизов, шаблон pull request (#7, PR #13).

### Fixed

- CORS по умолчанию разрешает и фронтенд из docker-compose на порту 8080 (#4, PR #11).
